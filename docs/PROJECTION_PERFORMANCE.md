# 投影分区可见性与外壳优化

## 实现边界

- 保留异步文件加载与现有单线程网格执行器。本轮没有修改菜单加载线程；其任务生命周期问题仍需另行修复。
- `core/ProjectionFrustum.h` 只做矩阵数学，`core/ProjectionVisibilityRules.h` 管理包围盒与调度规则，`runtime/ProjectionVisibility.cpp` 适配游戏相机。游戏对象不进入纯规则测试。
- 实际依赖为 LeviLamina 26.51.0。相机矩阵来自该包 `mc/deps/renderer/Camera.h` 的 `viewMatrixStack`、`projectionMatrixStack` 和内联 `getProjectionMatrix()`；沿用项目已有相机位置来源，没有新增位置偏移或猜测游戏函数。
- 只提取四个视锥侧面，不推断近远平面、反向 Z 或深度范围；矩阵、包围盒无效时保留绘制。已有相机位置硬编码来源仍需要在目标游戏版本内复核。
- 本轮遮挡优化是邻接内部几何剔除，不读取 GPU 深度，不提供 HZB 或视点相关的整栋建筑遮挡判断。

## 数据流与算法

1. 布局重建时，用现有结构变换函数转换分区八个角落的方块原点，再加入单位方块范围，得到构建包围盒。包含负坐标、非整分区尺寸、旋转和镜像。
2. 构建结束时，汇总实际 CPU 网格顶点范围，涵盖模型、液体、占位模型和纠错网格。通过 generation/revision 检验后，包围盒随网格一起发布；不使用原始分区范围裁剪越界模型。
3. 每个不透明阶段在纠错更新、网格接收之后计算可见性，绘制各桶复用结果。同步回退构建新网格后补算可见性。方块实体继续沿用原版渲染距离检查，避免用方块大小裁剪光柱等特殊渲染。
4. 单次线性扫描选择分区：可见增量、可见首次、周边预加载、后台分区，同级按距离排序。预加载范围将包围盒向外扩展 16 格。每第八次成功派发使用轮转选择，防止后台任务饥饿；未成功提交不消耗该次序号。
5. 不透明整方块被六个不透明整方块包围时跳过原版细分。半透明投影不采用这个额外捷径；玻璃、部分形状和缺失邻居不作为完整遮挡物。
6. 纠错单元只计算一次六邻面掩码，填充和线框复用；完全内部单元不进入网格生成。保留错误类型、错误状态、多余和缺失的优先级，保留外表面的逐格线框，不改变材料与放置数据。

视锥分类和任务选择均为 O(分区数)，不进行逐帧逐方块可见性检测。纠错表面邻居查询从填充、线框各六次，变为共享六次；生成量仍取决于结构形状。视野外分区后台补齐，因此当前版本不限制最终全结构显存驻留。

## 验证与游戏内对比

- 运行 `xmake -y` 和 `xmake -y LHoloLogicTests`，再运行 `build/windows/x64/release/LHoloLogicTests.exe`。
- 纯规则测试覆盖无效矩阵、透视侧面、视锥相交、12 种旋转镜像组合、负分区坐标、调度优先级和轮转公平性。
- 密实体素测试跨越 16³ 分区边界；32³ 实心体仅有 6×32² 个外表面，切到单层时重新暴露上下表面。
- 游戏内以相同文件、相机位置、画质和透明度对比：首次出现、转头补齐、切层、移动、旋转、镜像、液体、箱子、告示牌和穿透纠错。检查非对称结构与视锥边缘，不能只看完整立方体。
- 沿用每 64 个成功上传分区的 debug 汇总，增加可见分区数量与 revision 过期任务数量。可见数量是最近一次分类结果，未取得 CPU 顶点的分区保守计为可见。结合快照、构建、上传平均/峰值，分辨渲染筛选收益与初始化停顿。
- 没有游戏内采样时，不把算法查询次数减少或测试通过表述为实际帧率提升。整结构初始化、注册表解析和异步文件任务管理是独立后续任务。
